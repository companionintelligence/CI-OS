What it does not show (and why):

    gives (a unit test pins the file). The fallback was not run in a virtual machine
  * a zone chosen by hand on the new image: the unit tests pin that it is written as it is with no lookup; the Berlin of b124745 (docs/architecture/arm64.md, KI-29) went the same way into the
    installer, and Run 2 shows the installer applying an explicit zone. Not run again on this image
  * amd64, real hardware, a second run of either image, another country (the host's zone is the only one seen), Secure Boot
  * the section "cloud-config files, timezone keys only" of installed-facts.sh is empty in both records because the installer keeps its cloud-config as one escaped string: cloudcfg-after.txt is
    the read that works (the script is kept as it was run)
